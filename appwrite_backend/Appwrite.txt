Appwrite:

We are using Appwrite cloud which is a shared infrastructure where multiple other projects are hosted. Our project ID allows us to identify our project from all of them.

In self-hoisting it would follow a VPC like structure with all the projects in it belonging to you and you only 

Web platform: allows Appwrite to know that this application will be running in a browser and configure the CORS and other security protocols

Appwrite Web SDK: it's a developer kit with all the endpoints as a function so we have to configure them by ourselves

const account = new Account(client);
Handles the features of user login, registration and session features plus updates.

const databases = new Databases(client);
Handles database related functions like a new record creation, fetching a record 

We are creating the IDs as string cause that is how Appwrite deals with IDs

Security settings configured: 

Row security ON: Users can only access the rows which they are given permission for 
Table permission → what users can generally do with the table
Row permission → who can access a particular file row

the resume/profile files that were previously sitting inside your custom backend will now be uploaded into the Appwrite Storage bucket, and our JavaScript will retrieve/download them through Appwrite.
